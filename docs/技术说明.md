## 架构

```text
┌────────────────────────────┐
│          Vue 3 UI          │  设置界面 / 悬浮窗渲染 / 发送框（禁用态）/ 状态
└─────────────┬──────────────┘
              │ Tauri IPC（命令 + 事件）
┌─────────────▼──────────────┐
│         Rust Core          │
│  douyin: resolver/sign/    │
│  signer/ws/parser/proto/   │
│  login/event               │
│  tts: 队列 + Edge TTS      │
│  gift / welcome            │
│  state / commands /        │
│  connection / window /     │
│  config                    │
└─────────────┬──────────────┘
              ▼
   WebView2（签名页）+ Windows API（窗口 / 托盘 / winmm / DPAPI）
```

**弹幕事件流**：抖音 WS → `douyin::ws` 解帧 → `parser` → 事件分流

- `Danmaku` → `state::record_danmaku`（速率统计）+ `tts::on_danmaku`（朗读，独立筛选）+ `emit("danmaku")` → Overlay 渲染（前端再做一遍显示筛选）
- `Backing` → `gift::on_backing`（门槛 + 连击合并 → `emit("gift")`）+ `tts::on_backing`（礼物朗读，独立门槛与聚合）
- `Welcome` → `welcome::on_welcome`（去重限速 → `emit("welcome")`）

**连接流程**（`connection.rs`）

1. `connect_room(web_rid)`：校验纯数字 → 状态机置 `Connecting` → 起任务
2. `resolver::resolve`：`GET live.douyin.com/{短号}` 取 `ttwid` → `enter` 接口取 `room_id`、主播名、开播状态 → 合并登录 cookie（**必须保留 ttwid**）
3. 存入最近房间（含主播名）→ 生成一次 `user_unique_id`（整条连接复用）
4. 会话循环：`ws::run_ws_session`（签名 → 握手 → 10s 心跳 → 收帧 / 回 ack），出错按 `WsError::retryable()` 决定是否退避重连
5. 收尾：仅当自己仍是当前连接任务（取消令牌未被换走）才重置状态，避免旧任务误清新连接（`finish_connection`）

**连接状态双通道**：主窗口订阅 `room-status` 事件；悬浮窗额外每 2s 轮询 `get_connection_status` 兜底防事件丢失。

## 协议层实现要点

### 签名（`douyin/sign.rs` + `signer.rs`）

- 签名输入 = **13 个参数**（`SIGN_PARAM_ORDER`，顺序不可改）拼 `k=v` 用逗号连接 → MD5 小写 hex（= `X-MS-STUB`）→ webmssdk `getSign` → `X-Bogus`
- 必须跑 JS：隐藏窗口 `sign` 加载 `sign.html`（内含 `douyin-sign.js`），Rust 侧 `eval` 触发、页面经 `invoke('douyin_sign_reply')` 回包、`oneshot` 按 id 路由（Tauri 的 `eval` 拿不到 JS 返回值）
- 页面未就绪回 `NOT_READY` → Rust 内部重试 10×200ms；单次等待上限 3s
- 启动自检跑一次固定 stub，日志里能看到 `[sign] WebView2 签名自检通过：X-Bogus=…`

### WS 会话（`douyin/ws.rs`）

- URL 参数与顺序照探针实测（`build_ws_url`），`internal_ext` 必须 `encodeURIComponent` 转义
- 握手头：`User-Agent` + `Origin: https://live.douyin.com` + `Cookie`（含 ttwid）
- 收到帧：`decode_push_frame`（f8 是 gzip 的 `Response`）→ `decode_response` → 逐条 `parser::parse` → `need_ack` 时回 `PushFrame{f2=log_id, f7="ack", f8=internal_ext}`
- **解不开的帧只记日志、不中断会话**（抖音会夹带格式异常的帧）

### 登录（`douyin/login.rs`）

- 单独开窗口（label `douyin-login`，1180×820 / 最小 1000×680，**不能更窄**：抖音页面窄视口下会把登录入口整个藏起来）
- 每 1 秒读一次 `WebviewWindow::cookies()`，出现 `sessionid` 即视为成功 → 只保留抖音域下的 cookie → DPAPI 加密落盘 → 销毁窗口
- 5 分钟超时；用户关窗视为放弃。退出登录额外调 `clear_all_browsing_data()` 清 WebView2 的 cookie 库

## 字段与语义（实测）

| 内容 | 字段 | 备注 |
|---|---|---|
| 弹幕正文 / 昵称 | `WebcastChatMessage` f3 / `User.f3` | `Common.createTime` 是**毫秒** |
| 用户等级（荣誉等级） | `User.f23 = PayGrade` → `f6` | 回退：递归抠图标 URL 里的 `new_user_grade_level_v1_N.png` |
| 粉丝团（灯牌）等级 | `User.f24 = FansClub` → `f1 = FansClubData` → `f2` | 消息里**没有**灯牌名 |
| 礼物名 / 钻石价 | `WebcastGiftMessage` f15 = `GiftStruct` → f16 名 / f12 钻石价 | 1 钻石 = 0.1 元（**未与真实账单核对**） |
| 礼物数量 | `f6 = combo_count` | **累计值**，直接采用 |
| 进场 / 关注 / 点赞 | `WebcastMemberMessage` / `WebcastSocialMessage` / `WebcastLikeMessage` | 点赞的 `LIKE` 事件里 user 在 f5 |
| 真实 room_id / 主播名 / 开播状态 | `enter` 响应 `data.data[0].id_str` / `data.user.nickname` / `data.data[0].status`（2=直播中，4=已结束） | |

**坑**：`User.f6` **不是**用户等级 —— 绝大多数用户不带这个字段，带的人值是 1。真机曾因为它显示错等级。

## 配置与数据

- 配置目录：`%APPDATA%\com.douyindanmu.app\config.json`
- 保存内容：登录 Cookie、Overlay 样式与位置大小、弹幕过滤（等级门槛 + 敏感词）、TTS 配置（开关/音色/语速/音量/文案开关/队列上限/朗读筛选）、礼物列表配置（开关/门槛/条数/合并窗口）、礼物朗读配置（开关/门槛）、欢迎信息开关、最近房间列表（上限 10）
- 登录 Cookie 落盘前经 **Windows DPAPI 加密**（绑定当前用户与机器）：配置文件拷贝到其它机器/账户无法解密，需重新登录
- 数据仅存本机，不收集遥测、不上传日志
- 例外：开启朗读后，弹幕正文 / 打赏文案会发往微软 Edge TTS 服务合成语音；关掉开关即停（音色列表刷新同样访问该服务）

## 统一日志

`tauri-plugin-log` + `log` 门面宏，配置只在 `lib.rs` 的插件注册处一处（唯一配置点）。

- 落盘：`%LOCALAPPDATA%\com.douyindanmu.app\logs\douyin-danmu.log`（Tauri 的 LogDir 在 Windows 上是 LocalAppData）；关于页「日志」按钮用资源管理器打开
- 轮转：5MB + `KeepSome(7)`（插件默认 40KB + KeepOne，必须显式覆盖）；时区显式 `UseLocal`（默认 UTC 会差 8 小时）
- 输出目标：release 只挂 `LogDir`（`windows_subsystem = "windows"` 没有可写的 stdout），dev 额外挂 `Stdout`
- 业务前缀：`[douyin]`（连接/签名/会话）、`[sign]`（签名器自检）、`[login]`、`[tts]`、`[config]`、`[overlay]`、`[tray]`
- 安全：日志里不得出现完整 Cookie（`config.rs` 的 Cookie 解密失败只打原因，`crypto.rs` 的 Err 串只含字节长度与 `last_os_error()`）
